Six pillars, one thesis

Thesis: a context service is not retrieval over a repository — it is an evidence graph with time on every edge. Each pillar is a refusal, which is why the design is defensible under questioning. docs/02-architecture.md:5-6

1

Evidence before inference

Refuses to keep a claim whose quoted excerpt is not literally in the file at the cited lines. Gate 2 drops, never repairs.

03-ontology.md:198-201 · ADR-0005

2

Time on every assertion

Four timestamps per claim; a relationship without a validity window is a schema violation, not a shortcut.

04-temporal-model.md:16-22 · AGENTS.md:36-38

3

Claims, not facts

Reified assertions with polarity and modality. A proposal can exist in the graph without ever becoming true, and contradiction never deletes.

ADR-0002 · 03-ontology.md:58-68

4

Conservative identity

Merge only on declared identifiers. Resemblance is recorded as SIMILAR_NAME_TO and reported, never joined.

03-ontology.md:109-133 · traps T4, T5

5

Model proposes, compiler executes

The planner fills a JSON-schema-validated query plan. Cypher only ever comes from seven frozen templates.

ADR-0003 · 06-retrieval.md:14-37

6

Doubt is an output field

degraded, gaps, conflicts, DISPUTED and truncated are returned, not suppressed — including "the planner failed, here is hybrid search".

06-retrieval.md:158-168, 184-186

Architecture, end to end

One envelope between every stage. Pipelines are allowed to disagree; a single deterministic resolver decides what is currently true. Nothing after the resolver needs to know where a claim came from.

Why one store. The traversal-plus-vector query is a single Cypher statement, so the index cannot go stale relative to itself. ADR-0001
Why gates before the graph. A claim that fails a gate is dropped and logged; nothing downstream ever has to distrust its input. 03:192-206
Why the resolver is alone. All judgement sits in one deterministic, unit-testable place — which is also what lets four people work in parallel. ADR-0002

The four index layers — and which of them ship

Each layer exists because a query shape needs it. Only L0–L2 are in the five-hour spine; L3 is documented and cut for time (08:33 · 09:121-123).

L0 · Evidence

ships

Source · Span · Chunk — vector + full-text indexes. Answers "where exactly does it say that?".

L1 · Claim

ships

Reified assertions with four dates, status, confidence, CONTRADICTS. Answers "is this still true, and who disagrees?".

L2 · Entity

skeleton only

Materialised CALLS / READS_FROM / OWNS with the same temporal fields. Grows only where a spine pipeline lands.

L3 · Topic

documented only

Communities over L2, no LLM, indexed at query time. The piece that keeps query cost flat as the corpus grows.

Essential mechanics — the three machines

Extraction is deliberately stupid; resolution and querying carry the intelligence.

A · One envelope, three gates

Every pipeline emits the same record type, so a seventh source is a new function and zero edits elsewhere.

  • Schema gate — same model is the Ollama format constraint, so structure is right by construction.
  • Span gate — excerpt must occur verbatim at the cited lines. Drop, never repair.
  • Ontology gate — predicate must be in the enum and satisfy declared domain/range.

B · Time is a WHERE clause, not a ranking

Valid vs observed vs recorded is what lets the service say "the wiki was right when written" instead of "the wiki lies". Three canonical modes: current, point-in-time, full history.

StatusMeansCorpus case
VALIDtrue now, best evidenceSQLite on the stock read path
DEPRECATEDwas true, supersededRedis read cache · accounts-v1
PLANNEDaccepted, not yet effectivewarehouse console migration
PROPOSEDsuggested, never acceptedADR-004 People SSO
DISPUTEDsources conflict, no winnerSEC-22 suspected authz gap
UNKNOWNno usable time signalan undated code fact

Transitions: UNKNOWN→VALID (dated + authoritative + uncontested) · PROPOSED→PLANNED→VALID (accepted, then effective and corroborated) · VALID→DEPRECATED (superseded) · VALID→DISPUTED→{VALID|DEPRECATED} (conflict, then resolution by new evidence). The doc's diagram omits every entry edge into PROPOSED and PLANNED, so both nodes float in the render.

C · The resolver in seven steps — nothing is merged on resemblance

1
Score each claim: authority × time_conf × extractor_conf
2
Explicit supersession wins over inference; close the earlier valid_to
3
A later NEGATES closes every open ASSERTS for the same triple
4
An active PROHIBITION blocks promotion regardless of score
5
Rank survivors: winner VALID, older losers DEPRECATED
6
Ties within 0.15 → both DISPUTED. Never a coin flip.
7
Independence across source types corroborates: 1 − ∏(1 − cᵢ)
cap
Bound at ~10⁵ claims: quadratic per subject. Named, not hidden.

The five-hour constraint, drawn honestly

The plan is the scoring-optimal move — 45 of 100 points reward explained reasoning, not built features. Who builds what — four lanes

One owner per lane, four contracts between them, and only two real waits — both of which consume a file, not a running service. Detail and done-criteria: 10-workstreams.md.

A · extraction

Walker, router, deterministic pipelines

Emits a file. Never opens Neo4j. Owns the gate-2 mechanism: excerpt + start_line as a hint, resolved against the file, end_line derived.

ingest/ · done: claims.jsonl passes gates 1–3

B · core

Store, loader, resolver, time

Every judgement about what is currently true. Owns the Neo4j edition decision and the date-precision convention.

graph/ infra/ · done: T1 resolves, loader idempotent

C · search

Embeddings, hybrid, CQP, assembler

Longest chain, so the compiler and six templates are written before the event. Degrades to hybrid with degraded: true.

retrieval/ · done: tests/cqp green, no model

D · MCP / API

Two transports, fixtures, proof, demo

Fixtures at minute 20 unblock C. Three tools ship, six are documented — and that is said out loud.
